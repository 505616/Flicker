# 插件

> 插件是**可选**的：不指定就一个都不加载，程序的行为与从前完全一样。
> 加载方式有两种，都要**显式**给：命令行 `--plugin=<路径>`，或环境变量 `FLICKER_PLUGINS`。
> **命令行与图形界面都支持**（2026-10 起：图形界面里插件同样生效，`ctx.log()` 的输出进界面日志）。
> **程序不会自动发现插件** —— 不扫当前目录、不读 `package.json` 的字段、不找 `node_modules`。
>
> ✅ **接收模式（`flicker recv`，手机发到电脑）从 2026-10 起也支持插件** —— 那是第四个平面，
> 事件表在下面 §五·补。形状不一样：它**只有事件、没有贡献点**（落盘路径与逐块校验不允许插件插手）。

插件的用途是"在不改核心代码的前提下加自己的动作"。目前支持**四个平面**：
**发送端**（发文件的那个进程）、**中继**（自己部署的那台中转服务）、
**接收端页面**（对方打开的那个页面）与**接收端进程**（`flicker recv` 起的那个服务）。
每个平面有各自的钩子，插件在哪个平面被加载就只能用哪个平面的钩子 ——
用错了会**当场报错**（2026-10 起这条是真的：从前只拦"拼错的名字"，
一个订阅了 `run/start` 的中继插件会安静地什么都不做）。
**核心的加密、路径安全、销毁流程不允许插件改动**（见"能力边界"）。

## 一、三条设计原则

- **显式加载。** 插件是以你的权限运行的任意代码，而"顺手加载旁边的目录"会把
  "这个程序不需要装任何第三方东西"变成一句谎。所以只有 `--plugin=` / `FLICKER_PLUGINS`
  两个来源（页面平面则是写进显式清单），而且**加载了什么必须打在屏幕上**。
- **每件事都能回收。** 程序对用户的承诺是"所有传输用到的东西都是一次性的，用完就销毁"。
  插件要是能留下一个定时器、一个监听端口、一个临时文件，这句承诺就只对核心代码成立。
  所以插件里所有副作用都必须经过 `ctx.effect()` 登记，销毁链（中继关闭时、页面卸载时）会替它收尾。
- **写错要当场报错。** `ctx.on('manifset/scanned')` 这种拼写错误**立即抛错**，
  而不是"永远收不到事件" —— 后者会让插件作者去查自己的 bug，是最贵的一类排查。

## 二、怎么加载

```bash
# 发送端：单个插件
flicker send "D:\视频" --plugin=./my-plugin.cjs

# 发送端：多个插件（--plugin 可以重复给）
flicker send "D:\视频" --plugin=./a.cjs --plugin=./b.cjs

# 或者用环境变量（多个路径用 ; 或 : 分开，与系统一致）
FLICKER_PLUGINS=./a.cjs;./b.cjs flicker send "D:\视频"

# 只列出并校验插件，不传输（插件作者用它确认自己写对了）
flicker --plugins --plugin=./my-plugin.cjs

# 中继：自部署的中继用同一套写法
node relay/local.mjs --port=8787 --plugin=./my-relay-plugin.cjs

# 接收端页面：写进显式清单，然后重新内联并重新构建（页面必须自包含，只能构建期内联）
#   1) 把插件路径写进 web/page-plugins.json 的 plugins 数组
node gen/inline-plugins.mjs && node gen/gen-relay-page.mjs
```

插件文件必须是 **CommonJS 文件**（`module.exports`）。它可以：

- `require('node:…')` 内置模块
- **`require('./同目录的辅助文件')`** —— ✅ **2026-10 实测可以**（单文件产物里也行）。
  判据：`node _lab/probe-plugin-require.mjs`（对照组=自包含插件，实验组=require 同目录的
  `helper.cjs`，两组都必须跑通；跑通说明 require 真的返回了辅助文件的导出，而不是被忽略）。
  ⚠️ 能拆不等于该拆：拆出去的每个文件都要跟插件一起分发，而插件是**显式路径加载**的
  （不扫目录）—— 少一个文件，插件就在别人机器上加载失败。

页面插件则是**纯浏览器 JS**，不许 import/require、不许用 Node 的 API —— 内联脚本会在构建期硬检查。

## 三、事件与贡献点（发送端平面）

- `mode` 是 `'lan'`（局域网直连）或 `'relay'`（中继转发）。
- `summary` 是清单概览：`{ fileCount, dirCount, totalBytes, totalChunks, files[] }`，
  其中 `files[]` 每项是 `{ name, rel, size, chunks, kind }` —— **只有元数据，没有内容**。
- `ui/message` 是**同步**事件：处理函数必须同步完成，返回 Promise 会被忽略并记为插件错误。

| 名称 | 类型 | 什么时候 | 收到的数据 |
|---|---|---|---|
| `run/start` | 事件 | 参数解析完、开始扫描之前 | `{ mode, inputs, chunkBytes }` |
| `manifest/scanned` | 事件 | 清单与校验值都算好之后 | `{ mode, chunkBytes, summary }` |
| `ui/message` | 事件（同步） | 每次文本类界面输出 | `{ level, text }` |
| `transfer/complete` | 事件 | 传输结束、销毁之前 | `{ mode, ok, reason, bytes, fileCount }` |
| `gift/items` | 贡献点 | 组装清单时 | 返回 `{ name, data }` 或它的数组 |

`gift/items` 追加的文件对接收端来说就是**普通文件**，会正常落盘；
名字必须是单个文件名（不能带路径分隔符），也不许与已发送的文件重名。

## 四、事件与贡献点（中继平面）

- `relay/route` 在**任何路由之前**触发（连 `/health` 与首页都经过它），
  所以"给自建中继加一道访问控制"只需要这一个钩子。
- 返回 `{ status, body, headers }` 就直接结束这个请求：`body` 是字符串就原样返回，
  是对象就按 JSON 返回（并附上你的插件名，方便事后对账）。返回 `undefined` 表示放行。
- 房间的建立与销毁会通知插件；**重复操作不会重复通知**（房间已存在、房间已经不在了都不报）。

| 名称 | 类型 | 什么时候 | 收到的数据 |
|---|---|---|---|
| `relay/route` | 事件 | 每个请求进入路由之前 | `{ method, path, room, query, headers }` |
| `relay/room-created` | 事件 | 房间真的被创建时 | `{ room }` |
| `relay/room-destroyed` | 事件 | 房间真的被销毁时 | `{ room }` |
| `relay/health` | 贡献点 | 每次 `/health` 被访问 | 返回一个对象，字段并进响应 |
| `relay/store` | 贡献点 | 中继**启动时**取一次 | 返回一个存储后端对象，替换内置的内存存储 |

`relay/health` 加的字段会并进 `/health` 的响应（例如地区、运营方）。
**核心字段优先**：插件覆盖不了 `maxMessageBytes` 与 `protocol` ——
那两项是能力协商的依据，被覆盖等于中继对客户端说谎。

**`relay/store`：换掉"房间存在哪里"**（2026-10）

默认的房间存储是进程内存（`src/relay/room.js`）。想用磁盘 / 对象存储 / 数据库，
就让插件贡献一个存储后端。必须实现这些：

| 成员 | 说明 |
|---|---|
| `maxMessageBytes` | 能力协商的依据（正整数）。缺了客户端只能猜块大小，表现是"大文件必挂" |
| `ttlMs` | 房间存活时长；`status()` 里要如实报 |
| `create(id)` | 建房间（幂等）→ `{created, messages}` |
| `put(id, seq, data)` | 放一条 → `{seq, nextSeq}` |
| `putBatch(id, items)` | 放一批 → `{seqs, nextSeq}` |
| `get(id, seq)` | 取一条（**不删**）→ `{seq, data, nextSeq}` |
| `ack(id, upToSeq)` | 前缀确认并删除 → `{ackedBase, nextSeq}` |
| `status(id)` | 房间状态（pending / ackedBase / nextSeq / 年龄 / 空闲 / ttl） |
| `destroy(id)` | 销毁房间 |
| `stats()` | 维护用：房间数与消息总数 |

- **启动时就校验**：少一个方法当场报错并点名（缺哪个、是哪个插件）—— 不会拖到传到一半才
  `undefined is not a function`。
- **多个插件都贡献时，第一个说了算**：两个存储后端加在一起没有意义。
- 现成的例子：`examples/plugins/relay-disk-store.cjs`（消息写盘，ack 时删掉那份副本）。
- ⚠️ **只在自部署的 `relay/local.mjs` 形态下有效**：Worker 里装不了"从磁盘加载的插件"（没有磁盘），
  所以 Worker 形态仍然是内存存储。

## 五、事件与贡献点（页面平面）

- 页面插件的错误**不会中断传输** —— 这一点与另外两个平面**相反**。
  这里是**对方正在收文件**，插件是发送端/部署方装的扩展，它出错时把整场传输打断，
  受害的是那个只想把文件收下来的人。所以页面平面选择"吞掉、如实记下来、继续跑"。
- 页面上不存在"运行时加载插件"：接收端页面必须自包含（中继直接把 HTML 发出去，
  CSP 不允许任何外部脚本），所以页面插件是**构建期内联**进页面的。
- 内联意味着**任何页面插件都会改变页面指纹**（`--assets` 能核对）——
  "对方拿到的页面到底是什么"始终是可验证的。

| 名称 | 类型 | 什么时候 | 收到的数据 |
|---|---|---|---|
| `page/ready` | 事件 | DOM 就绪（下一个 tick） | `{ page }` |
| `recv/verified` | 事件 | 密码核对通过、清单解开 | `{ fileCount, totalBytes, files[] }` |
| `recv/file-done` | 事件 | 每个文件收完（已校验、已落盘） | `{ name, size }` |
| `recv/complete` | 事件 | 全部收完 | `{ fileCount, totalBytes, seconds }` |
| `page/actions` | 贡献点 | 接收完成时渲染 | 返回 `{ label, onClick }` 或它的数组 |

## 五·补、事件与贡献点（接收端进程平面，`flicker recv`）

> 这一节是 2026-10 补的**第四个平面**：手机把文件**推**到这台电脑时（`flicker recv`，
> 或图形界面里点「接收文件」），插件能看到什么。

- **只有事件，没有贡献点**。落盘路径规则、逐块校验、整文件摘要、销毁顺序都是接收端的安全底线，
  插件在这里能做的只是"知道发生了什么"（记账、通知、把清单写进自己的审计日志）。
  想改这些的话，`插件.md` §十那张表已经写明不允许。
- **插件出错不打断接收**：对方正在推文件，一个插件写坏了不该让这次传输失败（与页面平面同一个取舍）。
  错误**不会消失** —— 收尾时屏幕上一行一句打印出来，也会进 `plugins.errors`。
- **事件里永远不含密码与一次性链接令牌**：`receive/ready` 只给目录、端口、TLS 与上限。
- **顺序是真的**：插件按注册顺序被 `await`，所以"清单收到"一定排在"文件定稿"前面 ——
  拿这些事件写审计日志时不必自己排序。

| 名称 | 类型 | 什么时候 | 收到的数据 |
|---|---|---|---|
| `receive/ready` | 事件 | 服务已监听、链接与二维码已打印 | `{ dir, port, tls, limits: { maxFiles, maxBytes, maxChunkBytes } }` |
| `receive/peer` | 事件 | 手机连上来了（还没证明它知道密码） | `{ peer: { address, userAgent } }` |
| `receive/auth` | 事件 | 密码核对通过 | `{ peer, macProfile }`（`v1` 表示对方页面较旧） |
| `receive/manifest` | 事件 | 清单已解密、开工前的检查全部通过 | `{ files, skipped, totalBytes, totalChunks, diskFree }` |
| `receive/collision` | 事件 | 有同名文件（**只是通知**，改名/覆盖/跳过仍由用户决定） | `{ rel, existing }` |
| `receive/file-done` | 事件 | 整文件摘要校验通过、已改成正式文件名 | `{ rel, bytes, renamedFrom }` |
| `receive/file-failed` | 事件 | 整文件摘要对不上（半成品按设计留着） | `{ rel, reason }` |
| `receive/complete` | 事件 | 会话收尾成功 | `{ files, bytes, done, failed, skipped }`（后三个是文件名数组） |
| `receive/closed` | 事件 | 服务关闭、密钥已清零 | `{ reason }`（`finished` 或 `closed`） |

最小可用的例子（记录"这次收了什么"）：

```js
// recv-log.cjs
const { appendFileSync } = require('node:fs')

module.exports = {
  name: 'recv-log',
  apiVersion: 1,
  apply(ctx) {
    const log = (line) => appendFileSync('recv.log', line + '\n')
    ctx.on('receive/manifest', (e) => log(`清单：${e.files} 个文件 / ${e.totalBytes} 字节`))
    ctx.on('receive/file-done', (e) => log(`定稿：${e.rel}（${e.bytes} 字节）`))
    ctx.on('receive/complete', (e) => log(`结束：${e.done.length} 个成功`))
    // 重名时想知道"撞了哪个"，但决定权仍然在用户手里
    ctx.on('receive/collision', (e) => log(`同名：${e.rel} 已存在于 ${e.existing}`))
  },
}
```

## 六、写一个插件：发送端

```js
// my-plugin.cjs —— 自包含，只用内置模块
const { appendFileSync } = require('node:fs')

module.exports = {
  name: 'my-plugin',          // 会出现在界面、销毁清单与报错里
  version: '1.0.0',           // 可选，只用于显示
  apiVersion: 1,              // 必填：与程序提供的版本对不上会被**拒绝加载**

  apply(ctx) {
    ctx.log(`插件已就绪（Flicker ${ctx.info.flicker}）`)

    ctx.on('run/start', (e) => ctx.log(`模式=${e.mode} 块大小=${e.chunkBytes}`))
    ctx.on('manifest/scanned', (e) => ctx.log(`共 ${e.summary.fileCount} 个文件`))
    ctx.on('transfer/complete', (e) => ctx.log(`ok=${e.ok} 发出=${e.bytes} 字节`))

    // 追加一个文件一起送过去
    ctx.contribute('gift/items', () => ({
      name: '说明.txt',
      data: '这个文件由发送方的插件生成。',
    }))
  },
}
```

仓库里有**六个可以直接跑的示例**：`examples/plugins/hello-logger.cjs`（把这次传输记进日志）、
`attach-note.cjs`（往传输里追加一个文件）、`relay-gate.cjs`（中继的访问控制）、
`relay-disk-store.cjs`（中继的存储后端：消息写盘，ack 时删副本）、
`page-hello.mjs`（页面插件：收完后加一个按钮）与 `recv-log.cjs`（接收端进程：把"这次收到了什么"记账）。

## 七、给中继写一个插件

```js
// my-relay-plugin.cjs —— 自建中继的访问控制 + 审计
const { appendFileSync } = require('node:fs')

module.exports = {
  name: 'relay-gate',
  apiVersion: 1,

  apply(ctx) {
    const log = (line) => appendFileSync('relay-plugin.log', line + '\n')

    // 拦在路由之前：口令不对就直接 403
    ctx.on('relay/route', (e) => {
      if (e.headers['x-relay-token'] !== process.env.RELAY_TOKEN) {
        log(`拒绝 ${e.method} ${e.path}`)
        return { status: 403, body: { error: 'FORBIDDEN' } }
      }
    })

    ctx.on('relay/room-created', (e) => log(`房间建立 ${e.room}`))
    ctx.on('relay/room-destroyed', (e) => log(`房间销毁 ${e.room}`))

    // 让 /health 多报一个字段，方便自己核对部署
    ctx.contribute('relay/health', () => ({ operator: 'my-company' }))
  },
}
```

## 八、给接收端页面写一个插件

```js
// my-page-plugin.mjs —— 构建期内联进接收端页面
// ⚠️ 纯浏览器 JS：不许 import/require、不许用 Node 的 API（构建期会硬检查）
export default {
  name: 'my-page-plugin',
  apiVersion: 1,

  apply(ctx) {
    ctx.log('页面插件已就绪')

    ctx.on('recv/verified', (e) => ctx.log(`对方要发 ${e.fileCount} 个文件`))
    ctx.on('recv/file-done', (e) => ctx.log(`收到 ${e.name}`))
    ctx.on('recv/complete', (e) => ctx.log(`收完，用时 ${e.seconds}s`))

    // 往"接收完成"那块面板里加一个按钮
    ctx.contribute('page/actions', () => ({
      label: '复制文件清单',
      onClick: () => navigator.clipboard?.writeText('清单内容'),
    }))
  },
}
```

## 九、可回收：ctx.effect

```js
ctx.effect(() => {
  const server = http.createServer(handler).listen(0)   // 立刻执行
  return () => server.close()                            // 销毁时一定会被调用
})
```

`ctx.effect()` 会**立刻执行**传入的函数，并把它返回的清理函数登记进销毁链 ——
发送端的销毁清单里那一步叫「插件资源已释放」，中继在关闭服务时执行，
页面在卸载时执行。释放顺序是**逆序**（后建的先拆），一个插件清理失败也不会连累别的插件。

## 十、能力边界：插件不能做什么

| 不允许 | 为什么 |
|---|---|
| 改加密与握手（套件、密钥派生、降级保护） | 这是这个程序的全部安全性所在，不允许有例外 |
| 改接收端的落盘路径规则 | 那是"静默覆盖丢文件"的唯一防线 |
| 改清单里的 `sha256` / `size` 等字段 | 接收端按它们逐块校验，改了等于让校验说谎 |
| 覆盖中继 `/health` 的核心字段 | 能力协商据此选块大小，被覆盖等于中继对客户端说谎 |
| 决定销毁流程与顺序 | 销毁链属于核心；插件只能**登记**自己要清理的东西 |

## 十一、还没做的部分

| 计划 | 现状 |
|---|---|
| Cloudflare Worker 形态的中继插件 | ❌ **明确不做（2026-10 结论）**：Worker 跑在平台运行时里、没有磁盘，**运行时**装不了这套加载器。唯一可行的形态是"**部署期打包**"（wrangler 把插件一起 bundle 进去）—— 那是换一套插件模型，不是补一个缺口，所以不做。中继插件继续只在自部署的 `relay/local.mjs` 形态下可用 |

## 十二、安全提示

- 插件**不是沙箱**：它以你的权限运行，能读写你的文件、发起网络请求。
  只加载你自己写的或你看过源码的插件。
- 程序（以及自部署的中继）会把加载了哪些插件打在屏幕上；`--plugins` 可以只看不跑。
- 页面插件会**改变接收端页面的指纹**，而这个指纹是可核对的（`--assets`）——
  也就是说"对方收到的页面被谁改过"这件事跑不掉。
