# 在手机上用闪传

这份文档只讲**手机上那一侧** —— 手机屏幕上会看到什么、点哪里、卡住了先查什么。
命令行参数、部署中继、协议细节在 [`使用手册.md`](使用手册.md) 与 [`中继部署.md`](中继部署.md) 里，这里不重复。

## 一、先说结论

| 你要做的事 | 电脑上跑什么 | 手机上怎么打开 |
| --- | --- | --- |
| 电脑发、手机收（同一个 WiFi） | `flicker send <文件或文件夹>` | 扫屏幕上的二维码，或打开它给出的链接 |
| 手机发、电脑收（同一个 WiFi） | `flicker recv` | 扫二维码或打开链接 → 输入一次性密码 |
| 不在同一个网络 | `flicker send <文件> --relay=<你的中继地址>` | 打开中继链接 → 输入一次性密码 |

**手机一侧永远不需要装任何东西**：打开浏览器就是全部，没有应用商店、没有安装包。
手机也不能当"服务端"（浏览器做不到），所以让手机发文件时，是**电脑先起一个服务**、手机往上传。

## 二、电脑发、手机收（同一个 WiFi）

### 2.1 电脑上

```powershell
flicker send "D:\要发的文件.zip"
```

屏幕上会出现一个二维码、一条 `https://192.168.x.x:端口/?k=…` 的链接，和一个一次性密码。

### 2.2 手机上

1. 手机连**同一个 WiFi**（别用手机流量；开着 VPN 或代理（尤其全局模式）的先关掉）。
2. 扫二维码。扫不出来就把链接发到手机上打开（发给自己、或直接在手机上输入）。
3. 第一次打开会看到「此连接不安全」→ 点「高级」→「继续前往」。为什么见第五节。
4. 页面列出文件清单（只有名字和大小）→ 输入电脑屏幕上的**一次性密码** → 点「开始接收」。
5. 文件下载到手机上（安卓一般在「下载」，iPhone 在「文件」App 的下载项）。传完页面会显示收了多少。

## 三、手机发、电脑收（同一个 WiFi）

### 3.1 电脑上

```powershell
flicker recv
```

屏幕显示二维码、链接、一次性密码，以及"保存到"哪个目录（默认是这台电脑的「下载」）。

### 3.2 手机上

1. 同样先连同一个 WiFi，扫码或打开链接（第一次的「此连接不安全」同样处理）。
2. 输入一次性密码 → 点「连接电脑」。
3. 点「选择照片 / 视频」，或下面的「选择其他文件」。可以一次多选，但**不能选整个文件夹**。
4. 点「开始发送」，并且**别切到别的应用、别熄屏** —— 浏览器会把后台页面冻住。
5. 传完电脑上会自动打开保存目录，终端里打出销毁清单。重名时电脑会停下来问（换名字 / 覆盖 / 跳过）。

## 四、不在同一个网络（中继）

中继要先部署一次（见 [`中继部署.md`](中继部署.md)），之后固定用它：

```powershell
flicker send "D:\文件.zip" --relay=https://你的中继.你的用户名.workers.dev
```

它打印出来的链接长这样（房间名与盐都在 `#` 之后，中继服务器看不到）：

```text
https://你的中继.你的用户名.workers.dev/#k=<64 位十六进制>&s=<32 位十六进制>
```

手机打开这条链接、输入一次性密码就能收。**中继只转发不透明字节**，文件数据完全不经过它。

## 五、「此连接不安全」要不要点继续

要。局域网模式下，电脑临时生成一张**只用于这一次会话**的证书 —— 浏览器没在官方名册里见过的证书，都会先拦一下。

- 点「高级」→「继续前往」即可。数据本身是加密的；会话结束或超时后，电脑上的证书与密钥一起销毁。
- 唯一该犹豫的情形是：**你连的可能不是你以为的那台电脑**（比如同一 WiFi 里有人冒充）。
  命令行接收（`flicker recv <链接>`）会让人核对 8 位指纹；手机浏览器这一侧只能靠"地址对不对"判断，
  所以**别从陌生人那里拿链接**。
- 中继模式用的是正经 HTTPS 证书，不会有这个提示。

## 六、手机上做得到 / 做不到

| 做得到 | 做不到（浏览器的限制，不是程序偷懒） |
| --- | --- |
| 一次多选照片、视频、其他文件 | 不能选整个文件夹 —— 所以电脑上只有文件名，没有目录结构 |
| 传完用「分享」把文件交给别的 App | 不能把文件直接塞进某个 App |
| 页面会申请"屏幕常亮"（安卓可用） | iPhone 的 Safari 没有这个能力，只能靠别熄屏 |
| iPhone 的 HEIC 照片原样传 | 不转格式 —— 电脑上可能预览不了 |

## 六点五、手机发给另一台手机（不经过电脑）

**现在可以了**，只要有一个中继（见 [`中继部署.md`](中继部署.md)）。

> ⚠️ **这一节的功能没有在真手机上验过**：它是在真实浏览器里（两个标签页 + 本地中继）
> 逐字节跑通的。当前没有可用的中继与第二台手机，所以真机这一步还没做 ——
> 现象与描述不符请开 issue。技术上的取舍见 [`架构决策.md`](架构决策.md) §八。

1. 两台手机都打开中继地址的 `/send`（例如 `https://你的中继.你的用户名.workers.dev/send`）。
2. 发送方那一台：选文件 → 填一个一次性密码 → 点开始 → 等它给出链接。
3. 把**链接**和**密码分开**告诉另一台（链接发消息、密码打电话或当面说）。
4. 接收方那一台：打开链接 → 输入同一个密码 → 开始接收。

**这一页做不到的事**（浏览器的限制，不是程序偷懒）：

| 做不到 | 为什么 |
| --- | --- |
| 选整个文件夹 | 网页只拿得到"选中的文件"，拿不到目录结构 |
| 刷新后接着传 | 密钥与房间名只活在当前页面里，一刷新就没了 |
| 大文件"秒开始" | 开始前要整体读一遍算校验值（SHA-256），手机上会等一会儿 |
| 锁屏/切后台继续 | 浏览器会冻结后台页面；回来会继续，但被系统杀掉就得重来 |

> 为什么必须经过中继：**手机浏览器不能当服务端**（不能监听端口）。要让两台手机直接连，
> 得有一个双方都能打开的地方帮它们交换字节 —— 那就是中继。中继只转发密文，
> 看不到文件名、文件大小和内容。

## 七、打不开 / 传不动，按这个顺序查

1. 手机和电脑是不是**同一个 WiFi**（手机流量打不开局域网地址）。
2. 电脑上的程序还开着吗（关掉窗口或终端就等于销毁会话）。
3. Windows 防火墙：弹过询问要选「允许访问」；没弹过就去「允许应用通过防火墙」里给「闪传」打勾。
4. 电脑的网络是不是「公用网络」—— 公用网络下 Windows 默认拦住手机连进来，改成「专用网络」。
5. 手机上的 VPN / 代理先关掉（全局模式尤其会拦掉局域网地址）。
6. 二维码扫不出来就**改用链接**：二维码在本会话里修过（用独立解码器逐格验过），
   但不同相机 App 的宽容度不一样，链接永远是最稳的那条路。

## 八、想把图标放到主屏幕（可选）

- **安卓 Chrome**：右上 ⋮ → 「安装应用」（部分版本叫「添加到主屏幕」）。
- **iPhone Safari**：分享 → 「添加到主屏幕」。
- **Windows Chrome / Edge**：菜单 → 「应用」→ 「安装此站点为应用」。

三个已知的不完美（都不影响传文件）：
① iPhone 上图标目前大概率是**页面截图**（`apple-touch-icon` 给的是 SVG，iOS 传统上只认 PNG）；
② 局域网会话地址**每次都不一样**，装出来的图标只对这一次有用 —— 真正值得装到桌面的，是**中继地址**（固定）；
③ 页面里没有"安装"按钮：安卓靠浏览器自己弹，桌面和 iOS 要手动翻菜单。

## 九、真机验证清单（改了手机相关代码就跑一遍）

| 场景 | 怎么验 | 通过的标准 |
| --- | --- | --- |
| 手机收 | 电脑 `flicker send` 发一个小文件，手机扫码接收 | 清单出现、输密码后开始下载、结束后手机里能打开它 |
| 手机发 | 电脑 `flicker recv`，手机选一张照片发送 | 电脑上收到文件、终端打印的整文件哈希一致、iOS 的 HEIC 原样到达 |
| 锁屏 / 切后台 | 传到一半锁屏 30 秒再回来 | 页面回来会继续，或明确提示"已中断、可重试" —— **不许静默显示成功** |
