## 一、闪传是什么

闪传是一个**一次性**的文件传输工具。

- 你在自己的电脑上运行它，选好文件、设一个密码
- 对方**什么都不用装**，用浏览器打开一个链接，输入同一个密码
- 文件直接传过去，传完密码、密钥、链接、服务**全部立即销毁**

它和网盘、微信传文件的区别：

| | 闪传 | 网盘 / 微信 |
|---|---|---|
| 文件经过谁的服务器 | 局域网：**谁的都不经过**；跨网络：经过中继，但**只有密文**，中继解不开也看不到文件名 | 别人的服务器，而且是明文可读的 |
| 传完之后文件还在吗 | **不在**，服务已关闭、密钥已清零、中继上的房间已销毁 | 一直在别人服务器上 |
| 需要登录吗 | 不需要 | 需要 |
| 有大小限制吗 | 没有（受你磁盘限制） | 通常有 |
| 需要对方装东西吗 | **不需要** | 不需要（但需要账号） |

> **跨网络模式那句话值得再读一遍**：中继会经手你文件的**每一个字节**，
> 但那些字节是 AES-256-GCM 密文，密钥只存在于你和对方两台电脑上。
> 中继能知道"有人在传、大概多大"，不能知道"传的是什么"。
> 如果你连这一点都不接受，就自建中继（`中继部署.md`，一条命令部署到自己的账号），
> 或者改用局域网模式（数据完全不出本地网络）。

## 二、安装

### 2.1 你是哪一方？

| 你要做什么 | 需要安装吗 |
|---|---|
| **只是收文件** | ❌ **什么都不用装**。对方给你一个链接，用浏览器打开就行 |
| **要发文件给别人** | ✅ 需要装闪传 |

### 2.2 发送端的安装方式（三选一）

**方式 A：单文件版（推荐，最简单）**

1. 从 [GitHub Releases](https://github.com/) 下载对应系统的文件。每个平台发**两个**：
   **推荐下 `.zip`**（小 62%：94 MB → 36 MB），解压出来就是下面那个可执行文件；
   不想解压就直接下可执行文件本身（多下几十 MB）。
   - Windows：`flicker-x.x.x-windows-x64.exe`（或同名 `.exe.zip`）
   - macOS：`flicker-x.x.x-macos-arm64`（Apple 芯片）或 `-macos-x64`（Intel 芯片）
   - Linux：`flicker-x.x.x-linux-x64`
2. 放到任意文件夹，**双击运行**（macOS/Linux 首次可能需要右键 → 打开，或 `chmod +x`）
3. 完成。**不需要装 Node.js，不需要安装过程**

**方式 B：源码版（需要 Node.js）**

1. 确认电脑上有 Node.js 24 或更高版本：
   ```powershell
   node --version      # 应该显示 v24.x.x 或更高
   ```
   没有的话去 <https://nodejs.org> 下载安装（选 LTS 版本）
2. 下载项目文件夹，**双击 `启动.cmd`**（Windows）或 `启动.command`（macOS）
3. 如果双击没反应，说明 Node.js 没装好

**方式 C：npm 安装（给习惯命令行的人）**

```powershell
npm install -g flicker-transfer
flicker --gui
```

### 2.3 首次运行会看到防火墙提示

**Windows 第一次运行时会弹出"Windows 安全中心警报"，问你是否允许网络访问。**

这是正常的，也是必须的 —— 闪传需要监听网络端口，对方才能连进来。

- **请勾选"专用网络"**（家里/公司的网络）
- "公用网络"可以不勾（除非你确实要在公共网络上用）
- 然后点"允许访问"

> ❌ 如果点了"取消"，接收方将无法连接，会一直卡在"正在连接"。
> 补救：以管理员身份运行一次 `netsh advfirewall firewall add rule name="Flicker" dir=in action=allow protocol=TCP program="<闪传的完整路径>"`，
> 或者去"Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙"里手动勾上。

**macOS**：第一次会提示"是否允许传入网络连接"，选"允许"。
**Linux**：一般没有提示，如果用了 `ufw`/`firewalld` 需要手动放行端口。

## 三、三种连接方式，先选一种

两台电脑要能连上，必须满足下面**至少一条**。程序会自动探测，但你需要知道自己在哪种情况里。

### 情况一：两台电脑连着同一个 WiFi / 同一个路由器 ⭐ 最推荐

- **优点**：速度最快（每秒几十到上百 MB）、不需要互联网、不需要任何额外配置、不需要部署任何东西
- **怎么判断**：两台设备连的是同一个 WiFi 名字，或者同一个路由器的网线
- **典型场景**：家里两台电脑、办公室同一个网、手机连家里 WiFi 和电脑互传
- **发送端怎么用**：见 §4 或 §5，**不需要加任何参数**

### 情况二：两台电脑在不同地方（一个在家、一个在公司/外地）

- **前提**：需要先**部署一次免费的中继服务**（约 3 分钟，见 §5.5）
- **费用**：免费。一次传输只消耗个位数的请求次数，免费额度是每天 10 万次
- **发送端怎么用**：加 `--relay=https://你的地址.workers.dev`

### 情况三：其中一方有公网 IP

- 大多数家庭宽带**没有**公网 IP（运营商做了大内网，叫 CGNAT），程序会自动检测并告诉你
- 如果有，可以用 `--public=你的公网IP:端口`，不需要中继
- **怎么判断**：程序启动时会自动探测并在终端打印结论

> 如果你不确定自己属于哪种情况：**直接按情况一用**。两台设备在同一个网络下，体验最好、速度最快。
> 如果连不上，程序会明确告诉你原因和建议，不会让你猜。

## 四、图形界面：一步一步教你用

图形界面适合不习惯命令行的人。**任何平台都是同一个界面。**

### 4.1 打开

- **单文件版**：直接双击闪传程序
- **源码版**：双击 `启动.cmd` / `启动.command`
- **命令行**：`flicker --gui`

程序会打开一个窗口（或浏览器标签页），你看到的是**站点页**。

### 4.2 站点页长什么样

```
┌──────────────────────────────────────────────────────────────────────┐
│  闪传 Flicker                    🌐 English                  ● 空闲中 │
├──────────────────────────────────────────────────────────────────────┤
│  我要发文件                                                           │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  📥 把文件或文件夹拖到这里                                     │  │
│  │     也可以直接选整个文件夹，内部结构会一起传过去                │  │
│  │     [ 选择文件 ]  [ 选择文件夹 ]  [ 直接输入路径 ]              │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  或者，让别人发给我                                                   │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  📲 手机拍的照片传到这台电脑                                   │  │
│  │     点下面这个按钮，屏幕上会出现一个二维码；                   │  │
│  │     手机扫码打开页面，选照片发过来即可。手机不用装任何东西。   │  │
│  │     [ 接收文件 ]                                               │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  或者，从对方的链接接收                                              │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  🔗 对方也装了闪传？把链接和密码贴进来                         │  │
│  │     由这台电脑直接取回文件（逐块校验、整文件哈希），           │  │
│  │     不用开浏览器。                                             │  │
│  │     [ 从链接接收 ]                                             │  │
│  └────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

一屏之内，三个动作都能开始。**这就是"站点"的含义** —— 你既能发，也能收。

上面三块的区别要说清（这里很容易误解；后两块是**两种不同的接收入口**）：

- **我要发文件**：你**主动**把东西发出去，接着会让你设密码。
- **或者，让别人发给我**：点「接收文件」之后，电脑会起一个只在这台机器上的服务，
  屏幕上给出**二维码和链接**；手机扫码、输入电脑屏幕上显示的那个密码，把照片推过来。
  **电脑这侧不需要输入任何密码** —— 密码是"手机上要输入的那个"。
- **或者，从对方的链接接收**：**对方也装了闪传**时用这个。把对方屏幕上的链接和一次性密码
  贴进来 → 点「连上去看证书指纹」→ 确认这 8 位和对方屏幕上的一致 → 开始接收。
  文件由**这台电脑的程序自己**下载、逐块校验、整文件哈希，存在你选的文件夹里，
  收完还会通知对方销毁。中继链接请用浏览器打开（那种链接的接收端在网页里）。

右上角那个 **🌐 语言按钮**在发送端和接收端都有：点一下就在中文 / English 之间切换，
按钮上写的是**另一种语言**的名字（界面上写着 `English` 就是"点了会变英文"）。
它故意做得比较显眼 —— 需要它的人，往往正是看不懂当前界面的人。
选择会被记住，下次打开还是这个语言。命令行想换语言就加 `--lang=en`。

### 4.3 发送文件的完整流程

**第 1 步：选文件**
把文件拖进"我要发文件"区域，或点"选择文件"。可以一次选多个，也可以直接选整个文件夹。

**第 2 步：确认清单**
程序会显示：

```
📄 合同扫描件.pdf                892 KB
🎬 旅行记录 2024.mp4             2.31 GB
📁 照片/（3 个文件）             8.4 MB
──────────────────────────────────────
共 4 个文件                      2.32 GB
```

**清单是按"你加进来的东西"分组的**：加一个文件夹就是一行（显示文件夹名、
里面几个文件、多大），点一下展开看里面有什么。几十万个文件也不会卡 ——
明细是点开才去读的。

**加错了不用全部重来**：把鼠标移到那一行，右边会出现一个 `✕`，
点它只去掉**这一项**，别的都还在。所有项都去掉了，界面就回到最开始那一屏
（和刚打开时一样）。想一次全清掉就用「全部清空」。

**第 3 步：设置密码**
程序会自动生成一个密码，像这样：

```
correct-horse-battery-staple
```

- **可以直接用它**（推荐）
- 也可以自己输入一个
- 旁边有一个"复制"按钮

> **为什么默认密码是几个英文单词？** 因为你要把它**念给对方听**或者手打过去。
> 这种密码又好念、又好打，安全性却和 `aB3#xK9!` 差不多。

**第 4 步：选传输选项**

```
☑ 顺便把「闪传」也送给对方     ← 对方收到后也能把文件发给别人
☐ 限制传输速度
```

**第 5 步：开始传输**
点"开始传输"，页面会显示一个**二维码**和一个**链接**。

**第 6 步：把链接或二维码给对方**
- 面对面：让对方**扫二维码**（最快）
- 远程：把链接和密码通过微信/短信/任何渠道发给对方
- ⚠️ 链接和密码**分开发**更安全（比如链接发微信，密码打电话说）

**第 7 步：等对方输入密码**
对方输入相同密码后，你会看到"对方已连接"，然后开始传输。

**第 8 步：传完了**

```
✓ 传输完成     4 个文件 · 2.32 GB · 用时 21 秒

会话销毁清单
✓ 密码与会话密钥已清零
✓ 服务已关闭
✓ 一次性链接已失效
✓ 证书已从系统中移除
```

**到这里就结束了。** 关掉窗口即可。你的原始文件**没有被改动过**（闪传只读不写）。

### 4.4 接收文件的完整流程

接收有两种走法。先看你是哪一种：

**方式一：对方给你链接，你用浏览器打开**（对方没装闪传时只能这样）

**第 1 步**：对方给你一个链接。
**第 2 步**：用浏览器打开它。
**第 3 步**：你会看到对方要发给你的文件清单（只有名字和大小，看不到内容）。
**第 4 步**：输入对方告诉你的密码。
**第 5 步**：点"开始接收"。文件会一边下载一边写入磁盘。
**第 6 步**：完成后，程序告诉你文件存在哪里。

**方式二：双方都装了闪传 —— 在站点页里直接接收**（不用开浏览器）

**第 1 步**：在首页点「从链接接收」。
**第 2 步**：把对方屏幕上的**链接**和**一次性密码**贴进去，选好存到哪个文件夹（默认是"下载"目录）。
点「选择文件夹」弹出来的是**系统自带**的文件夹窗口 —— 里面有「新建文件夹」，也记得你上次去过哪；
万一这台机器上没有可用的系统窗口，程序会换成自带的那个选择器，那里同样有「新建文件夹」。
**第 3 步**：点「连上去看证书指纹」。这一步只是连一下、把对方的证书指纹算出来，**不传任何数据**。
**第 4 步**：核对屏幕上的 8 位指纹与对方屏幕上的是否一致。一致就点「指纹一致，开始接收」。
**第 5 步**：文件由**这台电脑的程序自己**下载，每块都校验、最后再算一次整文件哈希。进度就在这一页。
**第 6 步**：收完点「打开保存文件夹」就能看到文件。中途想停就点「停止接收」——已经收下的文件保留。

> **「不核对，直接开始」是给谁用的**：它等价于命令行的 `--insecure` —— 跳过证书检查，
> 一个冒充了对方地址的假服务就拦不住了。只有你确定这是自家局域网时才用。
> 密码和数据本身仍然是端到端加密的；这一关挡的是"你连的到底是不是对方那台机器"。

> **中继链接不行**：`https://<中继>/room/…` 那种跨网络的链接，接收端在网页里，
> 请用浏览器打开（命令行的 `flicker recv` 遇到它会提示你改用 `--browser`）。

> **大文件建议用 Edge 或 Chrome 打开链接。** Firefox 会先下载到内存里，
> 超过约 1 GB 可能失败。页面会自动检测浏览器并提醒你。

> **看不懂界面？** 右上角的 **🌐 按钮**可以在中文 / English 之间切换，
> 接收端和发送端都有。按钮上写的是"点一下会变成哪种语言"。

### 4.5 把闪传"固定"到开始菜单（可选）

如果你会经常用，可以把它变成一个真正的桌面应用图标，**不需要安装程序**：

**Edge / Chrome**：打开闪传的图形界面 → 右上角菜单 → **应用 → 安装此站点为应用**
（或者在地址栏右侧找"安装"图标）

之后你的开始菜单里就会出现"闪传"，打开是独立窗口、没有地址栏，看起来就是一个普通软件。

flicker send "D:\视频\旅行记录.mp4"

### 5.5 跨网络：部署一次中继（约 3 分钟，免费）

> 更详细的说明（协议、中继能看到什么、额度、故障排查）见 **`中继部署.md`**。

**只在两台电脑不在同一个网络时才需要做这一步。做一次，以后一直能用。**

**第 1 步：注册 Cloudflare 账号**
访问 <https://dash.cloudflare.com/sign-up>，用邮箱注册。**不需要信用卡。**

**第 2 步：安装部署工具**
先确认装好了 Node.js，然后：

```powershell
npm install -g wrangler
```

**第 3 步：登录**

```powershell
wrangler login
```

浏览器会打开一个页面，点"允许"，然后回到命令行。

**第 4 步：部署**

```powershell
cd flicker\relay
wrangler deploy
```

成功后终端会显示一行地址，类似：

```
https://flicker-relay.你的用户名.workers.dev
```

**这就是你的中继地址，记下来。**

**第 5 步：以后这样用**

```powershell
flicker send "D:\文件.zip" --relay=https://flicker-relay.你的用户名.workers.dev
```

然后把这个地址告诉对方（对方也是用浏览器打开它）：

```text
https://flicker-relay.你的用户名.workers.dev/#k=<房间名 64 位十六进制>&s=<盐 32 位十六进制>
```

`#` 之后的内容（房间名与盐）**浏览器不会发给服务器**，所以中继不知道别人要取的是哪一份数据。

> **中继服务器能看到我的文件吗？**
> **看不到。** 中继只负责让两台电脑互相找到对方，**文件数据完全不经过它**。
> 它甚至看不到文件名和文件大小。详见 §10。

### 5.6 手机往电脑传（`flicker recv`）

手机拍的照片、视频要传到电脑上。手机**不能**当服务端（浏览器做不到），所以反过来 ——
**电脑起一个服务，手机在浏览器里把文件推上来**：

```powershell
flicker recv
```

屏幕上会显示一个链接、二维码和一次性密码：

```
  ┌ 让手机打开这个链接 ──────────────────────────────┐
  │  https://192.168.1.5:54713/?k=r-hGTJ4D2GRWGINLL │
  │  ██ ▄▄ ██▀▄▀█ ▄▄ ██  （二维码）                    │
  └──────────────────────────────────────────────────┘

  一次性密码  k7m-3fq（手机页面上要输入它）
  保存到      C:\Users\你\Downloads
  ⏳ 等待对方发来…（超时 10 分钟后自动销毁）
```

> 手机那一侧的完整说明（屏幕上会看到什么、点哪里、卡住了先查什么）见 [手机使用指南.md](手机使用指南.md)。

**第 1 步**：手机连**同一个 WiFi**（和电脑在同一个路由器下）。
**第 2 步**：扫码（或把链接发到手机上打开）。第一次会看到一次「不安全」提示 →
点**高级 → 继续前往**（证书只可能在电脑上，数据仍然是加密的）。
**第 3 步**：输入屏幕上那个一次性密码，点「连接电脑」。
**第 4 步**：点「**选择照片 / 视频**」（或下面的「选择其他文件」），可以一次选多个。
选完页面会先算每个文件的校验值（手机上这一步略慢，但电脑靠它验证完整性）。
**第 5 步**：点「开始发送」。**别切到别的应用、别熄屏** ——
浏览器会把后台页面冻住（页面会尽量申请"屏幕常亮"，回来之后会接着传）。
**第 6 步**：显示"全部发完了"，电脑上自动打开保存目录，终端里打出销毁清单。

常用的几个参数：

| 参数 | 作用 |
|---|---|
| `--dir=路径` | 存到别处（默认是这台电脑的「下载」目录） |
| `--password=密码` | 自己指定密码（默认生成 6 位短码，手机上好念好打） |
| `--no-ask` | 重名一律自动改名，不弹"三选一" |
| `--no-open` | 传完不自动打开保存目录 |
| `--timeout=30m` | 等多久没人来就销毁（默认 10 分钟） |
| `--no-qr` | 不显示二维码（远程指导别人时用） |

> **重名怎么办**：默认会**停下来问你** —— 换个名字 / 覆盖它 / 跳过这个文件，
> 5 分钟不回答就按最安全的"换个名字"处理。加 `--no-ask` 可以关掉这个提问。

> **手机上那些限制，如实说**（不是程序偷懒，是浏览器做不到）：
> · 手机**不能选整个文件夹**，只能一个个（或按相册）多选文件 —— 所以电脑上只有文件名，没有目录结构；
> · 手机**不能选"存到哪里"**（那是电脑这边决定的），也**不能把文件塞进别的 App**；
> · iPhone 拍的照片是 HEIC 格式，**原样传**（不转格式），但电脑上可能预览不了 —— 需要的话在电脑上转；
> · 大文件传输时**手机得亮着屏**：切到别的应用，浏览器会把页面冻住（页面会请求"屏幕常亮"，
>   iPhone 的 Safari 没有这个能力，只能靠别熄屏）；
> · 传完之后手机上如果还想把文件发给别人，用接收端页面的「分享」按钮（Web Share），
>   那是浏览器唯一支持的"交给别的 App"的方式。

> **字太小的话**：三个页面（手机页、接收页、站点页）的**右下角**都有一个字号控件
> ——`A−` / 百分比 / `A+`，四档（100% / 115% / 130% / 150%），点中间的百分比就恢复 100%。
> 它只影响这一页的显示，不会改动任何传输内容；手机页与接收页的偏好在关掉标签后就不保留。

> **手机打不开链接？** 站点页的接收面板里也写着这几条，按顺序试：
> ① 手机和电脑连同一个 WiFi（别用手机流量）；② 电脑上的程序别关；③ 防火墙弹过询问就选「允许访问」，
> 没弹过就去「允许应用通过防火墙」里给「闪传」或 Node 打勾；④ 电脑的网络如果是「公用网络」，
> Windows 默认会拦住手机连进来 —— 改成「专用网络」；⑤ 手机开着 VPN / 代理（尤其全局模式）时先关掉。

> **图形界面里也有这个入口**：首页往下就是「**或者，让别人发给我**」→ 点「接收文件」→ 选保存目录 →「开始接收」。
> 屏幕上出现同一个二维码与一次性密码；传完会自动打开一次保存目录，也可以随时点「打开保存文件夹」。
> 重名同样是"停下来问"（换个名字 / 覆盖它 / 跳过这个文件）。

### 5.7 用另一台装了闪传的电脑接收（`flicker recv <链接>`）

场景：**两台电脑都装了闪传**，对方 `flicker send`，把屏幕上那条链接（和密码）发给你。
你可以直接把链接丢给浏览器，也可以用程序自己收：

```powershell
flicker recv "https://192.168.1.5:8443/?k=7f3a9c1e" --password=正确-马-电池-订书钉
```

它会做这些事，**每一件都会在屏幕上写出来**：

1. 先连上去，算出对方的**证书指纹**（比如 `A3F9C1D2`），然后问你："对方屏幕上显示的是这个吗？"
   —— 一致才继续。这是自签证书唯一的凭据：**不信 CA，信"两边看到的是同一张证书"**。
   一致就再跑一次并加 `--fingerprint=A3F9C1D2`，以后不必再问；确定是自家局域网可以加 `--insecure`
   （屏幕上会明确写着"这次没有核对"）。
2. 解开加密清单，**逐块校验**（每块都有哈希），再算**整文件哈希**，通过才改成正式文件名。
3. 重名**绝不覆盖**：自动存成 `名字 (1).扩展名`，并告诉你原来叫什么。
4. 收完通知对方"我收完了"——对方据此销毁密钥与链接（**用完即销毁**那条承诺的落点）。

**和浏览器的区别**（为什么值得用这条）：

| | 浏览器那条路 | `flicker recv <链接>` |
|---|---|---|
| 接收方要不要装程序 | 不要 | **要**（就是你现在这台） |
| 写盘 | Chrome/Edge 能边收边写；Firefox/Safari 先攒内存 | 一律 Node 直接写盘，**不占内存** |
| 大文件 | Firefox/Safari 上可能失败 | 多大都行（受磁盘限制） |
| "不安全"警告 | 有（对方证书装在他的机器上） | 没有，但**换成你自己核对指纹** |

> **图形界面里也有一模一样的一条路**：首页的「**或者，从对方的链接接收**」→ 贴链接和密码 →
> 点「连上去看证书指纹」→ 核对这 8 位 → 开始（见 §4.4 方式二）。界面背后调的是**同一个**
> `src/pull.js`，所以校验、改名、销毁的规矩完全一致。

> ⚠️ **中继链接不能用这条路**：`https://<中继>/room/…#<房间>:<盐>` 的接收端在网页里
> （中继把页面发给你、页面去房间里取），程序这边没有实现它。加 `--browser` 用浏览器打开即可 ——
> 中继用的是正规 HTTPS，浏览器那条路本来就没有门槛。

### 6.2 `send` 子命令

#### 关于 `--rate`（限速）

用来**别占满公司/家里的上行带宽** —— 传几十 GB 时把上行打满，会让视频会议卡住、网页打不开。

```powershell
flicker send "D:\电影.mkv" --rate=2M      # 限到约 2 MB/s
flicker send "D:\备份.zip" --rate=500K    # 限到约 500 KB/s
```

- 写法：`500K` / `5M` / `2G`，或直接给字节数（如 `1048576`）。K/M/G 按 1024 进制。
- **写错了会直接报错退出**，不会"悄悄不限速" —— 那种误解只有等同事抱怨网络卡才会被发现。
- 起始有约 1 秒的"突发额度"（桶是满的），所以**开头一小段会略快**，之后稳定在设定速率。
  实测稳态偏差 1–4%。

> ⚠️ **这条曾经是"文档里有、程序里没有"** —— `--rate` 会被当作未知参数静默忽略，
> 用户以为限了速、实际占满上行。现已真正实现，并且在两种模式下都有测试盯着
> （`test/rate.test.js` 验速率准确性，`test/e2e.test.js` 与 `test/relay-e2e.test.js`
> 分别验局域网与中继两条路径确实接上了）。

**图形界面里也能设**（2026-10 新增）：双击 `启动.cmd` 打开界面 → 选好文件 →
「传输选项」里的**限速**，可选 `不限速 / 1 / 2 / 5 / 10 MB/s`，或选「自定义…」
自己填（写法与命令行完全一致：`512K`、`5M`、`2G`）。

界面上写错了会**当场提示正确写法**并保持原来的设置不变 —— 理由与命令行那条相同：
把"看不懂的速度"当成不限速，比报错糟得多。

#### 图形界面里怎么选文件（不用手打路径）

点**选择文件**或**选择文件夹**会打开一个浏览窗口：左边列出盘符/文件夹，
点进去，选中的那一项就是"要发的东西"。

- **可以多选**：点右边的方框选中（再点一下取消），按住 **Shift** 连选一段
- **可以跨文件夹凑**：在 A 文件夹选两个、再进 B 文件夹选一个，最后一起确认
- **双击**某一项 = 直接发这一个（只加一个文件时最快）
- 两种模式的分工不一样：

| 点在哪里 | 选择文件 | 选择文件夹 |
|---|---|---|
| 文件的名字 | 选中 | —（只列文件夹） |
| 文件夹的**名字** | 进去 | **选中**它 |
| 文件夹左边的 **▸** | 进去 | 进去 |
| 右边的方框 | 选中/取消 | 选中/取消 |

- **「上一级」** 一路点能退回到"这台电脑"（盘符列表）

> **为什么不能像别的网页那样弹系统文件框**：浏览器有一个硬性规定 ——
> 网页拿不到你选中文件的**完整路径**。而这个程序的发送端是直接读原文件的
> （不复制、不占内存，几十 GB 才传得动），它需要的就是路径。
> 所以"选择"这件事由程序自己的本地服务来完成（它只监听本机回环地址）。

**加文件夹之后**，清单里显示的是**这个文件夹**（名字 + 里面几个文件 + 总大小），
点一下就能展开看里面有什么（子目录的层级也会保留）。

「直接输入路径」按钮仍然保留着 —— 那是给"我已经知道路径、就想粘一下"的人用的，
不是必经之路。

### 6.3 `recv` 子命令

`flicker recv` 有两种用法，靠**带不带链接**区分：

| 用法 | 说明 |
|---|---|
| `flicker recv`（或 `--listen`） | 起一个接收服务，等手机/别人把文件发过来（见 §5.6） |
| `flicker recv <链接>` | **用程序自己接收**：下载、逐块校验、落盘（见 §5.7）。中继链接要用浏览器，加 `--browser` |

`flicker recv`（接收模式）的参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--dir=<目录>` | 收到的文件存到哪里 | 这台电脑的「下载」目录 |
| `--password=<密码>` | 指定一次性密码 | 随机生成 6 位短码 |
| `--port=<端口>` / `--bind=<地址>` | 监听端口 / 监听地址 | 随机 / `0.0.0.0`（局域网可达） |
| `--timeout=<时长>` | 等多久没人来就销毁 | 10 分钟 |
| `--trust` | 把会话证书装进**本机**信任库 | 不装（手机上装不了，用不上） |
| `--no-ask` | 重名不问，一律自动改名 | 会问（三选一） |
| `--no-open` | 传完不自动打开保存目录 | 会打开 |
| `--max-files=N` / `--max-bytes=N` | 最多收多少个文件 / 多少字节 | 5000 个 / 200 GB |
| `--no-qr` / `--no-color` | 同上（全局） | — |

`flicker recv <链接>`（用程序自己接收）的参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--dir=<目录>` | 收到的文件存到哪里 | 这台电脑的「下载」目录 |
| `--password=<密码>` | 对方给的一次性密码；不给就提示你输入 | 会问 |
| `--fingerprint=<8 位>` | 对方屏幕上那个**证书指纹**；给了就不提问，对不上就失败 | 会问（核对） |
| `--insecure` | 跳过证书核对（屏幕上会明确写"没有核对"） | **不跳过** |
| `--browser` | 改用浏览器打开链接（中继链接只能这样） | 程序自己收 |
| `--no-open` | 收完不自动打开保存目录 | 会打开 |

### 6.3b `unpack` 子命令（解开赠品源码包）

对方如果勾了「顺便把闪传送给对方」，你收到的会有一份 **`.fkz` 源码包**（源码 + 全部文档）。
它就是一个装了多个文件的容器，用**收到的那份程序自己**解开即可：

```powershell
flicker unpack "D:\下载licker-0.1.0-source.fkz"
#   ✓ 解开 267 个文件（4161503 字节）→ D:\下载licker-0.1.0-source
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `<文件.fkz>` | 要解开的包（必给） | — |
| `--dir=<目录>` | 解到哪个目录（不存在会建） | 包旁边、用包名建一个目录 |
| `--force` | 目标文件已存在时**覆盖** | **不覆盖**（已存在就失败，并说清是哪一个） |

几点如实说：

- **不需要装 Node、也不需要别的工具**：解开用的是你手上这份程序。
- 包里是**纯源码 + 文档**，不是可执行程序。想用它跑起来才需要 Node 24+：
  在解开的目录里 `node bin/flicker.js --help`。只想看代码，用编辑器打开那个目录即可。
- 解包**不信任这个包**：路径穿越（`../x`）、绝对路径、Windows 保留名、
  两个条目落到同一个文件、非法 UTF-8 的文件名、被截断的包、末尾多出的字节 ——
  全部会被**明确拒绝**，而且拒绝时磁盘上一个文件都不会写出来。

### 6.4 时长与速度写法

| 写法 | 含义 |
|---|---|
| `30s` / `10m` / `2h` | 30 秒 / 10 分钟 / 2 小时 |
| `500K` / `10M` / `1G` | 每秒 500 KB / 10 MB / 1 GB（1024 进制） |
| `1048576` | 直接写字节数（每秒）也可以 |

### 6.5 `--window` 该设多少

`--window` 是**中继模式**的在途块数（一块 1 MiB）。它决定"同时有多少数据在路上"：

| 值 | 适用 |
|---|---|
| `1` | 停等。最省流量、最容易看清问题，但慢（实测约 4.7 MB/s） |
| `8`（默认） | 一般网络的最佳点。实测跨网络约 18–24 MB/s |
| `16` 以上 | **通常没必要** —— 实测吞吐在 28–30 MB/s 处饱和，那已经是链路上限 |

> 实测结论（见 `路线图.md` 第五·补章）：窗口从 8 加到 32，吞吐只涨约 18%，
> 说明瓶颈已经从"延迟"变成"你和中继之间的带宽"。
> **调大窗口不会让慢的链路变快**，只会让中继上多占几 MiB 内存。
>
> 另外：窗口单位是**块**，所以 `--chunk=2m` 之后同样的窗口能装两倍数据
> （见下一节）。

### 6.6 `--chunk` 该不该调

一般**不用管**（默认 `auto`）。它要解决的是一个很具体的问题：
接收端每取一块要等一个网络往返，所以"同时有多少数据在路上"决定跨网络的速度。
浏览器对同一个源最多开 6 条连接，于是"跑满链路"的条件是：

```
6 × 块大小  ≥  带宽 × 往返延迟
```

本机实测（256 MiB、往返 195 ms、链路 29.5 MB/s 封顶）：

| 块大小 | 端到端 |
|---|---|
| 1 MiB | 18.9 MB/s（6 MiB 在途，刚好够） |
| **2 MiB** | **26.3 MB/s**（12 MiB 在途，链路的 89%） |
| 4 MiB | 25.8 MB/s（**没有额外收益，只是更占内存**） |

所以默认的 `auto` 取 **2 MiB**，但它**不是想用就能用**：
一条消息就是一块，而中继有单条上限。发送端会先问中继"你最多收多大"
（`/health` 与创建响应里的 `maxMessageBytes`），然后取"想要的"与"对方允许的"里更小的那个。

| 你的中继 | `auto` 的结果 |
|---|---|
| 本程序 0.1.0 及以后部署的（声明 2 MiB） | 2 MiB |
| **更早部署的**（没有这个字段） | 自动回落到 1 MiB —— **不会报错、也不会传坏** |

想手动指定就写 `--chunk=512k` / `2m` / `4m`；写超过中继上限的值会被**压低**
（并在终端里说明"已按中继的上限压低"），而不是发出去被拒。

> ⚠️ **慢链路上不要盲目调大**：实测一条 5 MB/s 的链路上，1 MiB 与 4 MiB 的吞吐
> **完全一样**，但进度更新从每 212 ms 一次变成每 837 ms 一次，
> 丢一块也要多传 4 倍数据。块大小超过"带宽 × 往返"之后，多出来的部分只买到更粗的粒度。

> 顺带：接收端的预取缓冲 = 6 × 块大小，所以 2 MiB 的块意味着约 12 MiB 内存
> （仍然是常量级，与文件大小无关）。

## 七、传完之后

### 7.1 发送端

程序**不会改动、不会删除、不会移动**你的原始文件。它只读。
传输结束后：

- 如果用的是终端：进程退出，一切结束
- 如果用的是图形界面：可以关掉窗口，或者留着继续下一笔传输

### 7.2 接收端

文件保存在你选择的位置（图形界面下会弹出"保存到…"对话框；命令行下默认是下载目录）。

### 7.3 都没了是什么意思

传输结束后，下面这些东西**立即消失**：

| 消失的东西 | 说明 |
|---|---|
| 密码和密钥 | 从内存中被覆写清零 |
| 传输服务 | 端口关闭，链接失效 |
| 一次性令牌 | 链接无法再次访问 |
| 临时文件 | **从来就没有产生过**（这是设计目标） |
| 系统证书 | 会话证书从证书库中移除 |
| 中继上的房间 | 已删除（即使没删，几分钟后自动过期） |

**唯一留下的东西是接收方保存的那些文件本身** —— 那正是你要的东西。

## 八、故障排查

### 8.1 对方打不开链接

**症状**：对方浏览器显示"无法访问此网站"或一直转圈。

排查顺序：

1. **确认在同一个网络** —— 两台设备连的是同一个 WiFi / 路由器吗？
   - 如果对方连的是手机热点、或者隔壁的 WiFi，就连不上，需要用 `--relay`（见 §5.5）
2. **确认链接完整** —— 尤其 `?k=` 后面那一串一次性令牌，少一个字符都不行。建议直接扫二维码
3. **检查防火墙** —— 发送端第一次运行时是否允许了网络访问？（见 §2.3）
4. **隔离网络** —— 很多公司 WiFi、酒店 WiFi 开启了"客户端隔离"，同一个 WiFi 下的设备互相也连不上。
   这种情况只能用 `--relay`
5. **确认程序还在运行** —— 终端窗口没关吧？

### 8.2 一直卡在"等待对方连接"

说明对方还没打开链接，或者打开了但没输入密码。

- 让发送端终端保持运行
- 默认超时是 10 分钟，超时后会自动销毁，需要重新开始
- 想改超时：`--timeout=30m`

### 8.3 提示"密码不一致"

双方输入的密码不完全相同。**注意**：

- 大小写敏感（`Abc` ≠ `abc`）
- **空格也算** —— `correct horse` 和 `correcthorse` 不一样
- 中文输入法可能把连字符 `-` 变成了全角的 `－`

**建议**：直接复制粘贴密码，或者用二维码/链接让对方自己看。
连续失败 5 次后，本次会话会自动销毁（这是一个安全特性，不是 bug）。

### 8.4 传大文件时浏览器崩了 / 卡住

**原因**：你用的是 Firefox 或 Safari，它不支持"边收边写磁盘"，只能把整个文件放在内存里。

**解决**：
- 改用 **Edge 或 Chrome** 打开接收链接（最有效的办法）
- 或者让发送端加 `--one-file` 并分批发送

### 8.4.1 对方打开链接看到"不安全 / 您的连接不是私密连接"

**这是预期内的，不是出错了。** 原因是会话证书只装在**发送方**那台电脑上，
对方那台是第一次见到这张证书（详见 §10.3）。

**让对方这样做**：

1. 点页面上的 **「高级」**
2. 再点 **「继续前往 <地址>（不安全）」**
3. 之后就正常了 —— 只影响这一次

> 关键区别：警告说的是"**浏览器不认识这张证书**"，不是"内容没加密"。
> 文件内容依然是端到端加密的，中继和旁人都看不到。
>
> 想完全避开这一步：用 `--relay` 走中继（那边是正规 HTTPS 证书，两端都无警告）。

### 8.4.2 接收时浏览器问"是否允许此网站修改文件"

**这是保存文件所必需的，点「允许」即可。**

闪传在 Chrome / Edge 上是**边收边写盘**的（所以几十 GB 也不占内存），
写入磁盘需要浏览器的文件写入权限，于是会问这一句。

- 选**允许** → 正常接收（文件边收边写进你选的那个文件夹）
- 选**拒绝** → 分两种情况：
  - 文件不大（不到约 900 MB）：页面会**明确告诉你**"接下来会先收进内存再保存"，
    然后继续传完
  - 文件很大：页面会**停下来并告诉你重新点一次、选「允许」** ——
    因为几十 GB 没法先在内存里拼装，硬撑的结果是传到一半浏览器崩掉，
    那时候你已经等了很久了。**现在停下比传到一半崩掉划算**
- 在文件夹窗口点**取消** → 干净地中止，不会开始传输

- 那个"选择保存位置"的窗口也是同一件事：它在问"**存到哪里**"

**为什么不像普通网页那样直接下载**：普通下载是先把文件放进内存再落盘，
几十 GB 会直接把浏览器撑爆（§8.4 讲的就是这个）。边收边写是我们**故意**选的路径。

### 8.5 传输中断了

**先说好消息**：轻微的链路抖动**不会**再中断传输了。
Wi-Fi 闪一下、手机切个网、连接被重置 —— 两端都会自动重连
（最长会退避到 8 秒一次），界面上会显示"链路不稳，正在重连（第 n 次）"。
这类瞬时故障是长传输里最常见的失败原因，现在它不再毁掉整次传输。

**再说清楚做不到的部分**（这一条以前写错了，现在改正）：

| 情况 | 能不能接着传 |
|---|---|
| 传输中途网络抖动、自己恢复 | ✅ **自动继续**，不用你管 |
| 点"取消"后重新开始（发送端还在跑、房间还在） | ✅ 多文件时**已完成并校验过的文件会跳过**，不重传 |
| **关掉页面/浏览器再打开** | ⚠️ **块级别做不到，要从头开始**。若之前已有文件完整收完并通过校验，那些文件会跳过 |

**为什么"关掉页面"做不到**，这不是偷懒，是浏览器 API 的限制：

- 用 **Chrome / Edge** 时，文件是**边收边写进磁盘**的。但用来写文件的那个
  "句柄"在页面关闭后就失效了，重开后无法从第 N 字节接着写
  （浏览器的写入接口只能顺序写、且每次打开会清空文件）。
- 用 **Firefox / Safari** 时，文件是**先全部收进内存、最后一次性保存**的。
  页面一关，收到的部分就跟着没了 —— 没有东西可以"接着写"。
  所以这两个浏览器上，大文件我们本来就会提示你换 Edge 或 Chrome。

> **诚实的建议**：几十 GB 的传输**不要中途关页面**。
> 网络抖动现在会自愈；但关页面等于放弃这一趟。
> 如果必须中断，等它传完整个文件再关 —— 已完成的文件下次会被跳过。

如果你需要"关掉也能续"的能力，那需要换一个方案（例如把接收端做成常驻程序，
而不是一个网页）—— 那已经不是"对方什么都不用装"的形态了，属于另一个取舍。
**而且这个项目已经明确不做它（2026-10 决定）**：在浏览器里勉强做到，要同时放弃三条
你已经从这份文档里读到的承诺 —— 不用 IndexedDB 记账、链接首次访问即失效、
密码与会话密钥随本页释放。取舍写在 `路线图.md` 第 5 项与 §六。

### 8.6 速度很慢

| 原因 | 说明 |
|---|---|
| **走的是中继** | 跨网络模式下数据要绕一圈中继，速度取决于**你和中继之间的链路**，不是你和中继服务商之间的理论带宽。实测到 Cloudflare 的往返延迟约 195 ms；窗口已从 1 放宽到 8（实测 4.4×），但延迟本身是省不掉的 |
| 中继距离远 | 中继在哪个区域，就决定了绕多远。自建中继时选离你近的区域 |
| WiFi 信号差 | 用网线会快很多 |
| 磁盘慢 | 机械硬盘 + 小文件很多时，瓶颈在磁盘不在网络 |
| 对方是手机 | 手机的写入速度通常远低于电脑 |

> 想知道当前到底能跑多快，看发送端的实时速率显示。
> 局域网模式下的瓶颈几乎总是磁盘或 WiFi，不是程序。

### 8.7 提示"没有公网 IP，无法直连"

这是**正常的**，绝大多数家庭宽带都是这样（运营商做了大内网）。
程序只是告诉你"跨网络需要中继"，不是出错了。

### 8.8 二维码显示成一堆乱码

部分 Windows 老终端字体不支持二维码用的半块字符。三个办法：

1. 加 `--no-qr`，程序只输出文字链接
2. 用 Windows Terminal 或 PowerShell 7（显示正常）
3. 用图形界面（`flicker --gui`），那里的二维码是图片

### 8.9 macOS / Linux 上双击没反应

- macOS：可能被 Gatekeeper 拦了。右键点文件 → "打开" → 再点"打开"
- Linux：需要先加执行权限：`chmod +x flicker-*-linux-x64`

## 九、常见问题 FAQ

**Q：对方需要装什么吗？**
A：**什么都不用装**，只要有浏览器。电脑、手机、平板都一样。

**Q：文件会经过你们的服务器吗？**
A：**我们没有服务器。** 局域网模式下数据不出本地网络，两台电脑直连。
跨网络模式下会经过**你自己指定的那个中继**（可以自建，见 `中继部署.md`）——
这是必须说清楚的一点：**中继会经手文件的每一个字节**，但全是 AES-256-GCM 密文，
而且清单（文件名、目录结构、大小）本身也是加密的。

所以准确的说法是：

| 中继能知道 | 中继不能知道 |
|---|---|
| 有人在传、什么时候传 | 传的是什么内容 |
| 每条消息多大、一共多少条 | 文件叫什么名字、有几个文件 |
| 两端的 IP | 你的密码（**密码从不上线**） |

**Q：那"中继不可信"这件事怎么算？**
A：加密不依赖中继的可信。密钥由密码经 PBKDF2 + HKDF 派生，
只存在于你和对方两台电脑上；中继即使想作恶，也只能"拒绝服务"或"看元数据"，
**改不了文件内容**（每一块都有认证标签，改一个字节就会被接收端拒掉）。
详见 `行为与运行.md` §2.3 与 §10。

**Q：有大小限制吗？**
A：没有。能传多大取决于你的磁盘空间和网络。已测过几十 GB 的场景。

**Q：能传文件夹吗？**
A：能。文件夹会连同内部结构一起传过去。

**Q：能同时传给多个人吗？**
A：当前版本是一次性、一对一的。多人请分多次发送。

**Q：传输记录会被保存吗？**
A：程序**不写任何日志文件**。终端的输出关掉就没了（除非你自己重定向了）。

**Q：能续传吗？**
A：分三种情况，说法要准确：

- **网络抖动** → ✅ 自动重连继续，不用管（这是最常见的失败，现在会自愈）
- **同一页面内重试** → ✅ 已完成并校验过的**文件**会跳过，不重传
- **关掉页面再打开** → ⚠️ **块级别要从头开始**。浏览器没有"从第 N 字节接着写"的接口，
  关页面时没写完的文件就作废了（详见 §8.5）
  这个能力**明确不做**（2026-10 决定）：做它要放弃三条承诺，代价大于收益，理由同上。

所以我们不说"支持断点续传"这种笼统话 —— 那会让人以为关掉页面也能续。

**Q：对方收到的文件会不会被"改"？**
A：不会。传输时每个文件都计算 SHA-256 校验值，接收端会逐块校验，
最后比对整体哈希。任何一个字节不对都会被检测出来并中止。

**Q：能不能传完自动删除发送端的文件？**
A：**不能，也不会做这个功能。** 闪传对你的原始文件**只读**。
自动删除是危险行为，误删无法挽回，不该由一个传输工具来做。

**Q：为什么默认密码是几个英文单词？**
A：因为它要好念、好手打。`correct-horse-battery-staple` 的熵和 `aB3#xK9!` 差不多，
但你可以打电话念给对方，而不必依赖复制粘贴。

**Q：我不想要那个"顺便把程序送给对方"，可以关吗？**
A：可以。图形界面里取消勾选，命令行加 `--no-gift`。

**Q：手机能收文件吗？收完之后文件在哪？**
A：能收（**安卓真机实测通过**：局域网直连，传完自动销毁，见 `路线图.md`）。
但**"文件到哪去了"这件事手机上确实乱**，得如实说：

- **落盘位置由手机浏览器决定，不由本程序决定** —— 手机上不支持"让你挑一个文件夹"那种能力
  （电脑版 Chrome/Edge 支持，所以电脑上可以边收边写进你指定的目录）。
- **安卓**：一般进浏览器的下载目录（多数机型是 **Download / 下载** 文件夹）。
  各厂商的文件管理界面差别很大，个别老机型甚至没有独立的文件管理器 ——
  于是"下载到哪了"经常得靠翻浏览器自带的"下载内容"列表。
- **iPhone**：预期是进 **「文件」App → 下载项**（**未实测** —— 本项目没有真机验证过 iOS，
  也没有人反馈过结果；你试过的话欢迎告诉我们）。

**所以手机上最省事的做法是：收完之后点每个文件旁边的「分享 / 保存到…」**，
在系统面板里直接选"存储到照片 / 发给微信 / 存进文件" —— 那一步是**你自己挑目的地**，
不用去猜浏览器把文件丢哪了。

**Q：手机能发文件吗？**
A：手机**发**文件受浏览器限制 —— 浏览器不允许网页读取任意路径的文件，
所以你只能手动在文件选择器里挑文件，不能"选个文件夹自动发送"。

**Q：能在公网上直接用吗？**
A：能，但必须用 `--relay`（见 §5.5）。因为绝大多数家庭宽带没有公网 IP。

## 十、安全相关问题

### 10.1 密码是怎么被保护的

**你的密码从来不会离开你的电脑。**

两台电脑各自在本地用密码计算，然后互相核对"算出来的结果是否一致"，
通过交换一个随机挑战的应答来验证 —— 网络上传输的内容无法反推出密码，
也无法被重复使用（每次的挑战都是新的）。

即使有人在网络上抓包，他也拿不到密码，拿不到文件内容。

### 10.2 中继服务器能看到什么

| 能看到 | 看不到 |
|---|---|
| 有两个设备在通信 | 文件内容 |
| 一个随机的房间号 | 密码 |
| 通信的时间 | 文件名 |
| 双方的 IP 地址（网络层必然可见） | 文件大小 |

**而且这些信息在传输完成后立即被删除。**

### 10.3 关于系统证书

为了让对方打开链接时**不出现"此连接不安全"的红色警告**，闪传会：

1. 在启动时生成一个**只属于这次会话**的证书
2. 把它装到"**当前用户**"的证书信任库（**不需要管理员权限**，不影响系统其他用户）
3. 传输结束后**自动移除**

> ⚠️ **这一步只对"发起方这台电脑"有效。**
> 证书装在**你的**电脑上，不会跑到对方那台去 —— 所以：
>
> | 在哪台电脑上打开链接 | 会看到什么 |
> |---|---|
> | **发送方这台**（本机预览、自己测） | 零警告，页面正常渲染 |
> | **对方那台**（第一次） | 会看到一次"**您的连接不是私密连接 / 不安全**"提示 |
>
> 对方要做的是：点 **「高级」→「继续前往 <地址>（不安全）」**，然后就正常了。
> 这只影响第一次打开这一次，**数据仍然是端到端加密的** —— 警告说的是
> "浏览器不认识这张证书"，不是"内容没加密"。
>
> 为什么不做成"对方也不用点"：那需要**在对方电脑上装一张我们的根证书**，
> 而"让用户装一张陌生根证书"比"点一次继续前往"危险得多
> （那等于把对方所有 HTTPS 流量的信任权交出去）。这个取舍是刻意的。
>
> 想完全避开这一步：用 `--relay` 走中继 —— 那条路用中继自己的正规 HTTPS 证书，
> 两端都不会看到警告（代价是数据经中继转发，见 §10.2）。

> ✅ **本机零警告这个机制已在 Windows 10 + Edge 155 上实测验证通过**。
> 测试覆盖了三种浏览器模式（后台模式、可见窗口、无地址栏的应用窗口）和两种地址
> （`127.0.0.1` 与真实局域网 IP），并用一组"故意不装证书"的对照用例确认
> 测试方法确实能识别出安全警告页 —— 也就是说，这个"通过"不是测试太宽松造成的假象。

**证书本身是纯 JS 生成的**（不调用 `openssl`、不调用 PowerShell，不依赖任何外部程序），
所以生成这一步在所有平台上走的是同一份代码；而且它有一道硬判据：
**起一个 HTTPS 服务器，拿生成的 CA 当信任根去真连一次**。
连不上就是不合格 —— 不看任何 API 的返回值。

> ⚠️ **但"装进系统信任库"这一步只在 Windows 上做过**，其余平台**未在真机验证**。
> 而且这不是"还没来得及做"，两个平台各有各的硬原因：
>
> - **macOS**：系统自带的 `security add-trusted-cert` 就能做，不需要额外软件；
>   但 Apple 的说明写得很明确 —— 改用户信任设置**必须经过一次认证对话框**，
>   改系统域则需要 root。也就是说**没有"静默装进去"这条路**，
>   而闪传的定位是"启动即用、不弹窗问你密码"。
> - **Linux**：**没有零依赖的做法**。浏览器在 Linux 上不读系统证书目录，
>   Chromium 读的是 NSS 数据库（M146 起 `~/.local/share/pki/nssdb`，
>   之前是 `~/.pki/nssdb`），写入它需要 `certutil`，来自 `libnss3-tools`/`nss-tools`，
>   **默认没有装**；Firefox 还各用自己的库。
>   依据：[Chromium 官方文档](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/docs/linux/cert_management.md)。
>
> 所以这两个平台上请用 `--no-cert-install`，也就是下面的"手动信任"方式。
> 程序会在启动时**把该敲的命令原样打印出来**，但不会替你执行 ——
> 弹对话框和装软件包这两件事，不该发生在程序启动的路上。

如果你不接受任何程序动你的证书库，加 `--no-cert-install`：

```powershell
flicker send "D:\文件.zip" --no-cert-install
```

此时对方打开链接会看到一次安全提示，需要手动点"继续访问"。功能完全一样，只是多一次点击。

**异常情况下可能残留**：如果传输途中程序被强制结束（任务管理器"结束任务"、断电、蓝屏），
证书可能没来得及移除，会留在你的证书库里。程序**下次启动时会自动扫描并清理**这类残留。
你也可以手动检查：`certmgr.msc` → "受信任的根证书颁发机构" → 查找颁发者名为 `Flicker Session` 的项。
（macOS 上对应的是"钥匙串访问 → 系统/登录 → 查找 `Flicker Session`"，
Linux 上则是上面 `certutil -L` 列出来的那一项。）

### 10.4 拿不到密码的人能看到什么

只能看到一个要求输入密码的页面，**看不到任何文件信息** —— 连文件名和文件数量都看不到
（清单是加密的）。

### 10.5 这个程序不防什么（诚实说明）

- 不防**弱密码**。如果你自己设了 `123456`，别人可能猜到。程序默认生成的密码是安全的
- 不防**你的电脑已经被控制**（键盘记录器、木马）
- 不防**流量分析**：能看出"你在传东西"，看不出传的是什么
- 不防**你主动把链接和密码一起发给了不该给的人**

### 10.6 想自己核验

- 终端启动时会打印证书指纹，你可以手工比对
- 接收端页面可以展开"安全详情"，显示所用的加密套件和校验值
- 代码完全开源，密码学部分集中在独立模块里，便于审计

## 十一、卸载

闪传是**绿色程序**，不写注册表、不装服务、不留后台进程。卸载极简：

| 安装方式 | 怎么卸载 |
|---|---|
| 单文件版 | **直接删掉那个文件**，就没了 |
| 源码版 | 删掉整个文件夹 |
| npm 安装 | `npm uninstall -g flicker-transfer` |

**另外确认一下**（正常情况下程序已经自动清理了）：

- **Windows**：`certmgr.msc` → "受信任的根证书颁发机构" → 查找颁发者为 `Flicker Session` 的项，有就删掉
- **macOS**：钥匙串访问 → 系统 → 查找 `Flicker Session`
- **如果部署过中继**：`cd relay && wrangler delete`（或者不管它，免费额度用不完）
